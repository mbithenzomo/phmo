Pitfall: P22: Using different naming conventions in the ontology.

Explanation: Due to the re-use of concepts from other ontologies, some of the classes and properties in the PHMO use different naming conventions. Original PHMO classes use TitleCase for classes (e.g. MonitoredPerson) and camelCase for object and data properties (e.g. hasAgeGroup). Other imported ontologies have different naming conventions, such as the use of underscores and numeric codes in the Evidence and Conclusion Ontology (e.g. "ECO_0000000" for "Evidence").

Introduction back to ToC

The PHMO is a reusable general ontology for AI-based personal health monitoring applications. It supports the representation of system users, sensor data, medical conditions, health risks, health events, interventions, AI models, datasets, evidence, and explanations. The PHMO defines how these concepts are modelled. Condition-specific ontologies can extend the PHMO and define which concepts are modelled for a given condition. For example, the Atrial Fibrillation Monitoring Ontology (AFMO) extends the PHMO for atrial fibrillation. The PHMO supports three main functionalities: health risk assessment, health event prediction, and health intervention recommendation. Each output is generated by an AI model, such as a Bayesian network or a neural network. A health risk assessment estimates the probability that a monitored person will develop a medical condition. A health event prediction estimates the probability that a health event will occur within a short time window. A health intervention recommendation proposes a medical action, with an expected utility calculated by a Bayesian decision network. Each output is linked to the model that generated it, the inputs it was based on, and the datasets used to train and test the model. Health risk relationships and health interventions are also linked to supporting scientific evidence, and each piece of evidence is linked to its publication. This allows system recommendations to be grounded in, and explained through, the scientific literature. To support interoperability, the PHMO reuses concepts from established ontologies, including the Sensor, Observation, Sample, and Actuator (SOSA) ontology, the Smart Applications REFerence (SAREF) ontology, the Evidence and Conclusion Ontology (ECO), the FRBR-aligned Bibliographic Ontology (FaBiO), and the Explanation Ontology (EO).
